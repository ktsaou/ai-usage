# SOW-0015 - Park the lapsed MiMo plan

## Status

Status: completed

Sub-state: shipped; login tool verified against the parked configuration.

## Requirements

### Purpose

Stop the dashboard and the MCP from reporting a subscription that no longer exists as `down`, and stop the login tool from waiting for a sign-in that can never verify, while keeping the provider ready to resume when the plan is bought again.

### User Request

The user no longer subscribes to MiMo. Decision 1A: park it rather than remove it.

### Assistant Understanding

Facts:

- Since 2026-09-08 00:00 every MiMo poll returns `no token plan quota in response` (5238 consecutive failures at the time of writing); the console session itself is alive. That is what an account without a plan looks like to the fetcher.
- `parked: true` already exists: the scheduler skips it (`src/scheduler.ts:55`), the dashboard mutes it (`src/dashboard.html:452`), the MCP hides it (`src/mcp-server.ts:142`), and `test-all` skips it unless named (`src/test-all.ts:22`).
- `npm run login` (`src/login.ts`) hardcodes one tab per site and loops until every configured browser-session provider verifies. It did not consult `parked`, so a parked MiMo would still open a tab and block completion for 30 minutes; closing the window early skips the session save the Alibaba providers depend on (`src/login.ts:121-129`).

### Acceptance Criteria

- `config.json` marks `mimo` parked; the daemon does not poll it; the dashboard shows it parked; the MCP does not list it.
- `npm run login` opens only the Alibaba tab and completes once Alibaba verifies.
- Docs describe the parked state and that the login tool honours it.
